# ADG030 — mocked-subject

**Default severity:** warn

## What it detects
A test that patches the function it is supposed to test. A patch target is the
function's subject when both hold:

1. the test module imports that name with `from <module> import <name>`, and
2. the test is named after it (`test_parse_date_handles_utc` for `parse_date`) or calls
   it directly.

Recognised patches: `mock.patch("pkg.mod.name")` / `patch(...)` / `mocker.patch(...)`
(as decorator, context manager or call), `patch.object(obj, "name")`, and
`monkeypatch.setattr("pkg.mod.name", value)` / `monkeypatch.setattr(obj, "name", value)`.
Only patches that are new in this diff are reported.

## Why it matters
A test that replaces its subject with a mock checks the mock. It passes whatever the real
function does, so it looks like coverage while testing nothing.

## Example — flagged
```python
from dates import parse_date

@mock.patch("dates.parse_date", return_value=date(2024, 1, 1))
def test_parse_date(_):
    assert parse_date("2024-01-01") == date(2024, 1, 1)
```

## Example — not flagged
```python
from dates import parse_date

@mock.patch("dates.fetch_timezone", return_value="UTC")
def test_parse_date(_):
    assert parse_date("2024-01-01T00:00") == datetime(2024, 1, 1, tzinfo=UTC)
```

## Scope and known false positives
- Patching an imported name the test is named after for another reason (for example
  to count calls while testing a wrapper) is reported.
- Subjects imported as a module (`import dates`, then `dates.parse_date(...)`) are not
  recognised.
- Files that fail to parse are not analysed.
