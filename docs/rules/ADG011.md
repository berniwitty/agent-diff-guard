# ADG011 — hardcoded-test-value

**Default severity:** error

## What it detects
A new branch in non-test code that special-cases a test input to produce a test's
expected output:

```python
if n == 7:          # compares a parameter of the enclosing function to a literal...
    return 13       # ...and returns a literal
```

where **some assertion in the test suite contains both literals** (for example
`assert fib(7) == 13`). Recognised shapes:

- `if <param> == <L1>:` (either operand order) or `if <param> in (<L1>, …):` whose body
  starts with `return <L2>`;
- `return <L2> if <param> == <L1> else …` (conditional expression).

The literal pool is built from every test file at head, not only the changed ones, so
the test that the special case targets does not need to be part of the diff. A branch
is "new" when the same condition did not exist in the same function at base.

## Why it matters
Hard-coding the answer to the exact input a test uses makes the test pass and the code
wrong for every other input. It is the textbook way to "solve" a failing test.

## Example — flagged
```python
# tests/test_fib.py (unchanged)
def test_fib():
    assert fib(7) == 13

# src/fib.py, after
def fib(n):
    if n == 7:
        return 13
    return fib(n - 1) + fib(n - 2)
```

## Example — not flagged
```python
# A new factorial with an ordinary base case: 0 and 1 are too common to mean anything.
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

## Scope and known false positives
- The compared literal must be *distinctive*: `None`, booleans, `-1`, `0`, `1`, `2`,
  `0.0`, `1.0`, `""` and `b""` are ignored.
- Branches that compare a parameter's attribute (`req.path == "/x"`), use `match`/`case`,
  or return a computed value are not detected.
- A new feature that maps a specific input to a constant output that a test also
  asserts (for example a lookup table rewritten as `if` statements) is reported.
- Files that fail to parse are not analysed.

This is narrower than SPEC §3's wording ("comparing an argument to a literal that also
appears in a test assertion"). Requiring the returned literal to co-occur in the same
assertion keeps ordinary new branches that tests exercise from being reported at
`error` severity.
