# ADG010 — stub-body

**Default severity:** error

## What it detects
A non-test function or method that had real logic at base and whose body at head is only
stub statements: `pass`, `...`, `return`, `return None`, `raise NotImplementedError`
(with or without arguments), optionally preceded by a docstring. A `# TODO` comment
changes nothing because comments are not statements.

Functions are matched between base and head by qualified name (`Class.method`). Only
non-test Python files (see `classify.py`) are checked.

## Why it matters
Replacing an implementation with a stub makes type checkers and some tests happy while
deleting the behaviour. It is easy to miss in a large diff because the signature is
unchanged.

## Example — flagged
```python
# before
def total(items):
    return sum(item.price for item in items)

# after
def total(items):
    """Sum item prices."""
    raise NotImplementedError
```

## Example — not flagged
```python
# before
class Store:
    def save(self, record):
        self.db.insert(record)

# after: the method became an abstract interface method
class Store(ABC):
    @abstractmethod
    def save(self, record):
        ...
```

## Scope and known false positives
- Methods decorated with `abstractmethod` or `overload` at head are not flagged.
- A function that is new in this diff is not checked, even if its body is a stub.
- A real refactor that intentionally turns a function into a no-op (for example a
  deprecated hook) is flagged. Use `# adg: allow ADG010 reason="..."` to record why.
- When a name is defined more than once in a scope, the last definition is compared.
- Files that fail to parse at base or head are not analysed.
