# ADG020 — suppression-added

**Default severity:** warn

## What it detects
A suppression comment that is present at head more often than at base, in any Python
file (test or not):

- `# type: ignore` (with or without `[codes]`)
- `# noqa` (with or without codes), including the file-level `# ruff: noqa` and
  `# flake8: noqa`
- `# pragma: no cover`
- `# pylint: disable=...` and `# pylint: disable-next=...`

Only real comments count: the file is tokenized, so the same text inside a string literal
is ignored. Each `#` segment of a comment is checked, so
`# type: ignore[attr]  # noqa: E501` counts as two suppressions.

Suppressions are counted per exact directive (`noqa: E501` and `noqa: F401` are
different). A directive that only moved or was re-indented is not reported. When a
directive's count goes up, the occurrences on added lines are reported.

## Why it matters
A suppression makes a linter, type checker or coverage gate stop complaining without
fixing what it complained about. Each one may be justified, but each one deserves a
reviewer's look.

## Example — flagged
```python
# before
def load(path):
    return json.loads(open(path).read())

# after
def load(path):
    return json.loads(open(path).read())  # type: ignore[no-any-return]
```

## Example — not flagged
```python
# before
import os  # noqa: F401

# after: same suppression, the import just moved below a new one
import json
import os  # noqa: F401
```

## Scope and known false positives
- A prose comment that begins with one of the directive words (for example
  `# noqa is not needed here`) is counted.
- `# mypy: ignore-errors` and `# pyright: ignore` are not detected yet.
- Files that fail to tokenize at base or head are not analysed.
